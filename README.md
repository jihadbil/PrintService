# PrintService

وكيل طباعة محلي على Windows باستخدام .NET 10. عنوانه الافتراضي `http://127.0.0.1:5055`، وتفتح لوحة الاختبار على `/`.

## التشغيل

```powershell
dotnet run --project PrintService.Host --no-launch-profile
```

سياسة CORS المفتوحة وغياب المصادقة محفوظان عمداً لمرحلة الاختبار.

## محرك النصوص والصور والبديل

المحرك الحالي محفوظ في `LegacyPrintDocumentEngine` وهو الخيار الافتراضي:

```json
"Printing": {
  "DocumentEngine": "PrintDocument"
}
```

لتجربة البديل دون تغيير ملف الإعدادات:

```powershell
dotnet run --project PrintService.Host --no-launch-profile -- --Printing:DocumentEngine=Win32Gdi
```

أو غيّر `Printing:DocumentEngine` إلى `Win32Gdi` في `PrintService.Host/appsettings.json` ثم أعد تشغيل الوكيل.

البديل يستخدم `CreateDCW` و`StartDocW` و`DrawTextW` و`StretchDIBits` مباشرة. يفك الصور باستخدام SkiaSharp، ولا يستعمل `System.Drawing.Printing`. كلا المحركين يلف الأسطر الطويلة ويحافظ على اتجاه النص العربي ونسبة أبعاد الصور. عند غياب خيارات الصفحة يؤخذ مقاس الورق من تعريف الطابعة وتستخدم هوامش افتراضية صغيرة. يمكن للتطبيق تجاوز المقاس والهوامش لهذه المهمة فقط، ضمن ما يقبله التعريف.

عند اختيار **Microsoft Print to PDF** للنصوص أو الصور، يولّد الوكيل مسار حفظ داخل مجلد بياناته ويعيد الملفات في `outputFiles`، دون طلب اسم ملف. ESC/POS يتطلب طابعة تفهم أوامره ولا يتحول تلقائياً إلى نص. طابعات OneNote وdoPDF التفاعلية تُرفض برسالة واضحة. التعرف على هذه الطابعات الافتراضية يعتمد على أسمائها؛ لا تغير أسماءها أثناء الاختبار.

Microsoft لا تدعم `System.Drawing.Printing` داخل خدمة Windows أو ASP.NET، لذلك يبقى `PrintDocument` خيار توافق للاختبار. اختبار البديل على الطابعة الافتراضية لا يضمن عمل كل تعريفات الطابعات أو حسابات الخدمة؛ يجب التحقق تحت حساب خدمة Windows وعلى الجهاز المستهدف قبل النشر.

المراجع: [قيد المحرك الحالي](https://learn.microsoft.com/dotnet/api/system.drawing.printing)، [واجهات GDI الأصلية](https://learn.microsoft.com/en-us/windows/win32/printdocs/how-to--print-using-the-gdi-print-api).

## ملفات PDF

يستخدم الوكيل SumatraPDF للطباعة إلى الطابعات الفعلية، مع التحقق من رمز الخروج والمهلة. يتطلب هذا تثبيت SumatraPDF من [المصدر الرسمي](https://www.sumatrapdfreader.org/download-free-pdf-viewer)، أو وضعه في `tools/SumatraPDF.exe` بجانب ملفات التطبيق، أو تحديد مساره:

```json
"Printing": {
  "PdfExecutablePath": "C:\\Program Files\\SumatraPDF\\SumatraPDF.exe",
  "PdfTimeoutSeconds": 60
}
```

لا يُستخدم Edge أو فعل `printto` الخاص ببرنامج الملفات الافتراضي، ولا تُرسل بيانات PDF خاماً عند فشل المعالج. الملف المؤقت لا يُحذف قبل خروج المعالج أو التأكد من إيقافه. إذا تعذر إيقاف المعالج يبقى الملف للمراجعة. طباعة ملف PDF إلى طابعة ملفات افتراضية غير مدعومة في هذا المسار؛ إرسال النصوص والصور إلى Microsoft Print to PDF مدعوم. [خيارات SumatraPDF ورموز الخروج](https://www.sumatrapdfreader.org/docs/Command-line-arguments).

## الطلبات ومنع التكرار

```javascript
const jobId = crypto.randomUUID(); // مرة واحدة لكل فاتورة، خارج حلقة إعادة المحاولة
const bytes = new TextEncoder().encode("فاتورة مبيعات\nالإجمالي: 150 د.ل");
const contentBase64 = btoa(Array.from(bytes, b => String.fromCharCode(b)).join(""));
const payload = { jobId, printerName: "Microsoft Print to PDF", documentType: 3,
  systemId: "restaurant", contentBase64, copies: 1, jobTitle: "Invoice",
  page: { paperName: "A4", margins: { leftMm: 5, rightMm: 5, topMm: 5, bottomMm: 5 } } };
// أعد إرسال payload نفسه عند انقطاع الاتصال؛ لا تنشئ jobId جديداً لإعادة المحاولة.
const response = await fetch("http://127.0.0.1:5055/api/print", {
  method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(payload)
});
const result = await response.json();
```

الأنواع: `1` ESC/POS، `2` PDF، `3` نص UTF-8، `4` صورة. اسم الطابعة اختياري ويستخدم الطابعة الافتراضية الحقيقية فقط؛ لا يختار أول طابعة عند غياب الافتراضية.

الطلب المكرر بمعرف ومحتوى وإعدادات متطابقة يعيد النتيجة المحفوظة. تغيير المحتوى أو الإعدادات مع المعرف نفسه يعيد `409 Conflict`. إذا لم ترسل `jobId` يولّد الخادم معرفاً جديداً لكل طلب، وبالتالي لن يستطيع ربط إعادة المحاولات. توجد حدود قابلة للضبط: 10 نسخ، 10MiB للمستند، 25 مليون بكسل للصورة، 32 مهمة نشطة/منتظرة، وطابعتان تعملان بالتوازي. كل طابعة تستقبل مهمة واحدة في الوقت نفسه؛ امتلاء القائمة يعيد `429` ويمكن إعادة المحاولة بالمعرف نفسه.

بعد قبول المهمة، انقطاع HTTP يلغي انتظار العميل فقط. الخدمة تكمل المهمة وتسجلها. عند إيقاف الوكيل تُلغى المهام المنتظرة ويُنتظر انتهاء المهام النشطة ضمن مهلة الإغلاق؛ إيقاف العملية قسرياً قد يترك نتيجة غير مؤكدة.

يمكن الاستعلام عن `GET /api/jobs/{jobId}?systemId=restaurant`. عند عدم إرسال `systemId` تظل واجهة الاستعلام القديمة تعمل للمهام القديمة. النتيجة تحتوي `systemId` و`status` و`completedCopies` و`spoolerJobIds` و`outputFiles`:

| الحالة | المعنى |
| --- | --- |
| `ValidationFailed` | طلب غير صالح، لا توجد طباعة ولا يحجز المعرف |
| `Queued` / `Processing` | مهمة مقبولة وقيد الانتظار أو التنفيذ |
| `Submitted` | تأكد إرسال كل النسخ إلى مخزن الطباعة، وليس اكتمال الطباعة على الورق |
| `Failed` | تعذر التنفيذ قبل إرسال أي نسخة مؤكدة؛ النتيجة محفوظة |
| `Unknown` | بدأ الإرسال ثم حدث خطأ، أو توقفت الخدمة قبل حفظ النتيجة النهائية |
| `Conflict` | المعرف مستخدم لطلب مختلف |
| `Busy` | القائمة ممتلئة؛ الطلب لم يُقبل ويمكن إعادة المحاولة |

لن يعيد الوكيل تلقائياً مهمة `Failed` أو `Unknown`. راجع مخزن Windows أولاً؛ لإعادة الطباعة المقصودة استخدم معرفاً جديداً. في لوحة الاختبار يحتفظ الزر بالمعرف عند انقطاع الاتصال أو عدم تأكد النتيجة؛ زر «بدء مهمة جديدة» يتيح محاولة جديدة مقصودة. بعد نجاح المهمة، الضغط مرة أخرى ينشئ مهمة جديدة.

## فصل إعدادات التطبيقات عن الخدمة

`appsettings.json` يحتوي إعدادات تشغيل عامة فقط: المنفذ والمحرك ومسار برنامج PDF ومجلد البيانات وحدود الموارد. لا تحفظ فيه اختيار طابعة الكاشير أو المطبخ أو أي دور يخص تطبيقاً معيناً. اختيار الطابعة والشعار وتنسيق الفاتورة وعدد النسخ ومقاس الورق والهوامش تبقى في React أو التطبيق المستدعي.

`systemId` معرف اختياري للتطبيق (حتى 64 حرفاً إنجليزياً أو رقماً أو `. _ -`، دون حساسية لحالة الأحرف). يخزن الوكيل المهام حسب الزوج `(systemId, jobId)`، لذلك يمكن للمطعم والمحاسبة استخدام `invoice:123` بشكل مستقل. نفس المعرف والمحتوى داخل التطبيق نفسه لا يطبع مجدداً. المعرف للتصنيف وليس للمصادقة. الطلبات والسجلات القديمة التي لا تحتويه متوافقة، ويمكن أيضاً الاستمرار بأسلوب المعرفات المسبوقة باسم النظام.

### خيارات الصفحة لكل طلب

```json
{
  "systemId": "restaurant",
  "jobId": "invoice:123",
  "documentType": 3,
  "contentBase64": "SGVsbG8=",
  "copies": 1,
  "page": {
    "paperWidthMm": 80,
    "paperHeightMm": 200,
    "landscape": false,
    "margins": { "leftMm": 2, "rightMm": 2, "topMm": 3, "bottomMm": 3 }
  }
}
```

اختر `paperName` من `supportedPaperSizes` في بيانات الطابعة، أو أرسل `paperWidthMm` و`paperHeightMm` معاً؛ لا تجمع الأسلوبين. عرض الورق بين 20 و1000 مم وارتفاعه بين 20 و3000 مم، وكل هامش بين صفر و100 مم. الهوامش التي تغيب قيمها تستخدم 3 مم، وقد تقيد الحدود المادية للطابعة المساحة القابلة للرسم. الأبعاد تصف الورقة في الوضع العمودي، و`landscape: true` يقلب اتجاهها لهذه المهمة.

خيارات الصفحة لا تغير تفضيلات Windows ولا إعدادات طلبات التطبيقات الأخرى. إذا استبدل التعريف الأبعاد المطلوبة بمقاس آخر، يُرفض الطلب قبل إرسال أمر طباعة. بعض التعريفات، ومنها Microsoft Print to PDF على جهاز الاختبار، لا تقبل الأبعاد المخصصة؛ استخدم مقاساً معرّفاً مثل A4 أو A5. لا تضاف نماذج ورق مشتركة إلى Windows تلقائياً.

النصوص والصور تدعم المقاس والاتجاه والهوامش في المحركين. ملفات PDF تدعم طلب مقاس قياسي مثل A4، بينما اتجاه الصفحة والهوامش والأبعاد المخصصة تحدد داخل الملف. ESC/POS يحدد التنسيق داخل البايتات الخام. الخيارات غير المدعومة تُرفض بوضوح. ويُطلب من محرك PDF نسخة واحدة لكل استدعاء مع تجاهل إعدادات الطباعة المضمنة في الملف، حتى لا تتضاعف النسخ خارج حدود طلب API.

### عميل جاهز للاستخدام في React

انسخ `PrintService.Host/wwwroot/print-client.js` إلى تطبيقك واستورده. لا يعتمد على React أو أي مكتبة إضافية. تستخدمه لوحة الاختبار نفسها، وتحفظ إعدادات كل تطبيق محلياً في المتصفح؛ الخدمة لا تحتفظ بتفضيلات التطبيقات.

```javascript
import { createPrintClient } from "./print-client.js";

// أنشئ العميل مرة واحدة، مثلاً خارج المكوّن أو داخل useMemo.
const printer = createPrintClient({ systemId: "restaurant", profileId: "cashier" });
const availablePrinters = await printer.getPrinters();
const saved = printer.getSettings();

// عند حفظ اختيار المستخدم؛ لا تكرر الحفظ في كل render.
printer.saveSettings({
  printerName: "Microsoft Print to PDF", copies: 1,
  page: { paperName: "A5", margins: { leftMm: 3, rightMm: 3 } }
});

const job = printer.createTextJob({ jobId: "invoice:123", text: "فاتورة مبيعات\nالإجمالي: 150 د.ل" });
const result = await printer.print(job);
// عند انقطاع الاتصال أعد printer.print(job) بنفس الكائن؛ لا تعِد إنشاء محتوى متغير.
const state = await printer.getJob(job.jobId);
```

الإعدادات منفصلة حسب عنوان الوكيل ومعرف التطبيق ومعرف تثبيت المتصفح و`profileId`. أسماء مثل `cashier` أو `kitchen` تخص التطبيق المستدعي فقط. `deviceId` محلي لهذا المتصفح وملف المستخدم؛ لا يمثل معرف عتاد ولا يزامن الإعدادات بين المتصفحات. إذا أردت مزامنة تفضيلات أجهزة المستخدمين، احفظها في خادم تطبيق React بمعرف الجهاز الذي يديره تطبيقك. يمكن تمرير `storage` مخصص للعميل عند الحاجة.

`createTextJob` يشفر العربية بـUTF-8 ويأخذ لقطة ثابتة للإعدادات. `createJob` يدعم أنواع الملفات الأخرى مع `contentBase64`. يمكن تجاوز الإعدادات لكل مهمة، أو إرسال `page: null` لاستخدام إعداد الطابعة الحالي. `print` يعيد النتائج المنظمة حتى في حالات `Unknown` و`Conflict`؛ لا ينشئ معرفات جديدة ولا يعيد الطباعة تلقائياً.

## التخزين والتشغيل كخدمة

افتراضياً تُحفظ البيانات في `%LOCALAPPDATA%\PrintService` لحساب تشغيل الوكيل:

- `jobs`: سجل المعرفات والنتائج وبصمة المحتوى، دون تخزين محتوى الفاتورة نفسه.
- `output`: ملفات Microsoft Print to PDF.
- `temporary`: ملفات PDF المؤقتة.

السجل لا يُحذف تلقائياً للحفاظ على منع التكرار بعد إعادة التشغيل. إزالة سجلاته تسمح بإعادة طباعة معرفات قديمة. نسخ التطبيق لا تشترك في السجل إلا عند استخدام مجلد البيانات نفسه؛ يُؤخذ قفل حصري لمنع تشغيل وكيلين عليه.

لتغيير الحساب أو الانتقال من التشغيل اليدوي إلى خدمة Windows، اضبط `Printing:DataDirectory` على مسار كامل ثابت، وانقل السجل عند إيقاف الوكيل، وامنح حساب الخدمة صلاحيات القراءة والكتابة عليه وعلى ملفات الإخراج. يجب أن يرى حساب الخدمة الطابعات المطلوبة؛ طابعات حساب المستخدم ليست بالضرورة متاحة لحساب الخدمة. `UseWindowsService` يدعم الاستضافة لكنه لا يثبت الخدمة تلقائياً.

`/api/health` يتحقق من تشغيل Spooler واكتشاف الطابعات ويعرض توفر محرك PDF. حالات الطابعات تأتي من Windows وتعريف الطابعة؛ لا تضمن اتصال الجهاز مادياً إذا لم يحدّث التعريف حالته. OpenAPI متاح في بيئة Development فقط، ولا تعرض `/api` رابط توثيق غير موجود في Production.

## التحقق

```powershell
dotnet build PrintService.slnx
dotnet test PrintService.slnx
node --test PrintService.Tests/print-client.test.mjs
```

الاختبارات تستخدم طابعات ومحرك طباعة وهميين، ومعالج PDF منفصلاً لا يطبع. تغطي التكرار المتزامن وبعد إعادة التشغيل، انقطاع العميل، الفشل الجزئي، حدود النسخ والحجم، أنواع المستندات، بيانات UTF-8، صف الانتظار، حالات Windows، والتعامل مع نتائج برنامج PDF والمهلة وحذف الملفات المؤقتة.

اختبار اختياري ينتج ملفات محلية فقط بالمحركين، ويتطلب وجود الطابعة باسم Microsoft Print to PDF:

```powershell
dotnet run --project PrintService.Tests -- --verify-virtual-printer
```

يعيد مسارات ملفات النصوص العربية والصور تحت مجلد مؤقت خاص بالتحقق. لا يرسل الاختبار إلى طابعة ورقية.

```powershell
dotnet run --project PrintService.Tests -- --verify-page-options
```

يتحقق هذا الاختبار أيضاً من A5 الأفقي وخيارات الأبعاد المخصصة، ثم يطبع بمقاس الطابعة الافتراضي مرة أخرى للتأكد من عدم تغييره. إذا رفض التعريف المقاس المخصص يسجل `Unsupported` ولا يستبدله بمقاس مختلف.
